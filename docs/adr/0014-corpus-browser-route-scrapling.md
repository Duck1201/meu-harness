# Coleta de Corpus com Scrapling: limpeza de conteúdo oculto e rota de browser por sintoma

O Corpus é contexto de todo Turn seguinte, então o que entra nele por scrape precisa sair mais limpo do que entra no `web_fetch`, que o modelo lê uma vez. O extrator nativo lê HTML como um leitor de texto e não como um navegador: um bloco com `display:none`, um `aria-hidden` ou um `<template>` entram no índice como qualquer parágrafo, e é exatamente aí que uma página hostil esconde instrução para o modelo. O Scrapling passa a ser o extrator HTML da ingestão atrás de `corpus.ingestion.html_extractor`: a limpeza dele (ruído, conteúdo oculto, comentário, caractere de largura zero) roda antes, o Markdown resultante segue pelo mesmo leitor de upload `.md`, e menus continuam saindo pela heurística de densidade de links do extrator nativo. Só a limpeza é do Scrapling; o download continua no transporte guardado do harness, com IP fixado pelo EgressGuard, porque o fetcher HTTP do Scrapling resolve DNS sozinho e perderia essa garantia.

O segundo problema é o site que monta o conteúdo em JavaScript: o crawl HTTP recebe a casca e indexa nada. Para essa página — e só para ela, reconhecida pelo sintoma de texto visível abaixo de `thin_page_chars`, no mesmo espírito do escalonamento do `web_fetch` — o scraper pede uma renderização a um Chromium efêmero do Scrapling. O browser é o risco: ele pede subrecursos que ninguém revisou, e qualquer um pode apontar para a rede interna. Toda requisição dele passa pelo EgressGuard num handler de `page.route` registrado antes da navegação, WebSocket é recusado, a URL final é revalidada, e a instalação do guard é conferida depois do fetch, porque o Scrapling engole exceção do `page_setup` e navega assim mesmo — sem essa conferência o guard falharia aberto. A rota é disparada só pela coleta que o Operator inicia, nunca é tool do modelo, e o resultado carrega `UntrustedWebTaint` como qualquer página coletada. O `StealthyFetcher` existe para passar por proteção anti-bot; ele fica atrás de `stealth` e os termos do site continuam sendo responsabilidade de quem coleta.

Ficam registradas as lacunas que o guard por rota não fecha. O browser resolve DNS por conta própria, então entre a validação e a conexão existe a mesma janela de DNS rebinding já aceita em `RELEASE-PENDING.md`; e requisição feita por service worker não passa por `page.route`. As duas razões pesam para os dois interruptores nascerem desligados — `html_extractor: builtin` e `browser_escalation.mode: disabled` — e só mudarem com o experimento de ingestão medido, e para os fetchers de browser serem um extra opcional (`uv sync --extra browser` seguido de `scrapling install`) que o harness nunca exige para subir.
